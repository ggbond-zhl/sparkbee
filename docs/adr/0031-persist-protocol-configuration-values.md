# 协议配置项以 PostgreSQL 为当前值来源

SparkBee 将每个桩实例的协议配置项当前值持久化到 PostgreSQL；Actor 启动时从数据库加载，界面编辑与 CSMS 通过 OCPP `ChangeConfiguration` 下发的修改都必须先成功写入数据库，再更新运行中的 Actor。数据库写入失败时不得只修改内存：界面编辑返回失败，`ChangeConfiguration` 返回 `Rejected`。该选择以数据库可用性对配置修改的约束，换取界面、Actor、服务重启恢复和 CSMS 观察到的配置值保持一致。

每个桩实例按配置键逐行保存完整协议配置目录的当前值，而不是只保存偏离默认值的覆盖项。数据库记录实例值与更新时间，配置项的只读性、值类型、范围、重启要求、说明和默认值继续由协议核心定义；新增桩实例初始化完整目录，已有桩实例或未来新增的协议配置键只补齐缺失记录，不覆盖已有值。这样避免代码默认值变化使旧桩实例在未被编辑时发生配置漂移。

协议配置项与桩实例基本配置采用不同的运行期编辑边界：桩实例运行中仍允许界面或 CSMS 修改可写协议配置项，两条入口复用协议核心的校验与变更状态；只读项只能查看。立即生效的配置修改成功后更新运行行为，需要重启的配置允许持久化并返回重启要求，界面必须明确提示其在桩实例重启后生效；桩实例停止时的修改在下次启动时加载。

界面按单个配置项独立保存，不批量覆盖完整目录。每条持久化记录带递增版本号，界面修改必须提交读取时的预期版本；如果同一配置项已经被 CSMS、其他页面或内部同步修改，后端拒绝覆盖并返回冲突，用户刷新该项后重新决定。不同配置项可以独立修改，成功变更后各自递增版本号。

协议核心的内部配置同步同样采用强一致写穿，不降级为 best effort。`BootNotification` 返回的心跳间隔只有在持久化成功后才能成为运行值；写入失败时本次 Actor 启动失败并断开，不允许使用数据库中不存在的新值继续进入 running。`NumberOfConnectors` 在枪口拓扑增删时同步持久化，未来新增的内部配置同步也必须在相关运行操作完成前持久化成功。

第一版只持久化并展示协议核心注册的内置协议配置目录，不允许界面新增、重命名或删除配置键，也不接受没有类型、范围和运行行为定义的厂商自定义键。未知键继续由 OCPP `ChangeConfiguration` 返回 `NotSupported`；后续新增协议配置项必须先在协议核心注册定义及行为，再由目录补齐机制加入各桩实例。

内置配置项是否被当前运行核心实际消费，不影响其可编辑性：凡协议定义目录标记为可写的项，界面与 CSMS 都允许修改并持久化，`GetConfiguration` 返回其当前值。第一版不增加 `active`、`declarative` 等行为支持分级，也不因缺少运行副作用而把内置可写项改为 `NotSupported`；团队接受部分修改只改变可查询配置值而不改变模拟行为。

桩实例运行期间由 Actor 作为协议配置项的单写者：界面修改与 CSMS `ChangeConfiguration` 进入同一串行配置命令边界，依次完成校验、带版本持久化、内存目录更新和运行副作用。界面不得在 Actor 运行时绕过它直接写配置表。桩实例停止时由后端协议配置模块复用协议核心校验后写入；Actor 启停与配置修改互斥，发生生命周期竞态时修改必须完整完成或返回可重试冲突。

每条持久化记录包含 `pendingRestart`。需要重启的配置项被修改时将其设为真，无论修改发生在运行或停止状态；只有 Actor 加载该值并成功进入 running 后才能清除，启动失败时必须保留。界面使用该持久状态展示和筛选待重启生效项，不通过更新时间与进程内启动时间推断。

协议配置页面通过 HTTP 加载完整目录的初始事实，并复用单桩 SSE 接收 `configuration.changed` 增量；成功的界面修改、CSMS 修改和内部同步都发布包含键、新值、版本、来源、更新时间及重启状态的结构化协议事件，前端据此更新单项查询缓存。失败不发布变化事件。该事件按现有协议事件策略持久化供运行调试台回看；SSE 仍不承担历史回放。

每条记录持久化受限枚举的最后修改来源：`ui`、`csms`、`internal` 或 `initialization`，并与协议配置变化事件使用相同语义。第一版没有登录用户模型，因此不保存自由文本操作者；页面展示最后更新时间和来源，后续鉴权上线时再扩展用户标识。

新建桩实例时必须在同一数据库事务中创建桩实例和完整协议配置目录，任一步失败则整体回滚。应用启动时在进入 ready、恢复活动交易或启动任何 Actor 前，为所有未删除桩实例阻塞补齐缺失配置键；首次发布和未来新增协议配置键都只插入缺失记录，不覆盖已有值。补齐失败时服务保持未就绪，不采用首次页面访问时才写入的懒初始化。

界面允许对单个可写配置项恢复协议核心定义的默认值，并把它作为带版本保护的普通 `ui` 修改处理；不提供整目录批量重置，避免一次操作同时改变心跳、交易、计量和授权行为。

第一版不建立独立配置变更历史表。配置记录长期保存当前值、版本、更新时间和最后修改来源；成功变化通过现有协议事件保留 7 天用于短期调试回看，不提供任意历史版本恢复、差异比较或长期审计时间线。

共享测试环境继续沿用 ADR-0025 的公开、无登录边界，第一版允许任何能够直接访问后端 API 的调用方读取或修改可写协议配置项。团队接受匿名修改心跳、计量、授权和交易相关行为的风险；内置目录、类型、范围、版本冲突与事件记录仍必须强制执行。未来登录模块上线时，协议配置读取和修改必须纳入授权，至少修改操作不得继续匿名开放。

协议配置目录按协议版本隔离，持久化身份为 `chargingPointId + protocol + key`，Actor 和页面只加载桩实例当前协议版本的目录。未来切换协议时初始化或补齐目标协议目录，不复用其他协议的同名键，并暂时保留旧协议目录供切回使用。

协议配置记录不设置独立 `deletedAt`，作为 ADR-0008 的明确例外：配置项不能被用户单独删除，其可见性跟随父桩实例；桩实例软删除时目录记录保留并由父资源查询边界隐藏，未来物理清理桩实例时再通过外键级联删除。协议切换保留旧目录，内置键弃用则使用专门迁移处理。

界面、CSMS 和内部同步之间不设置永久来源优先级，按单写边界中最后一次成功持久化的修改作为当前值；协议交互产生的内部事实可以覆盖界面值，界面也可随后再次修改可写项。对于 `HeartbeatInterval` 等已知会被协议流程同步的配置项，界面必须提示其可能被 CSMS 返回值覆盖。

界面编辑表示直接调整模拟桩本地协议配置，不主动向 CSMS 发送 OCPP 消息；OCPP 1.6 的 `ChangeConfiguration` 仍只表示 CSMS 下发命令。SparkBee 发布的 `configuration.changed` 是内部结构化协议事件而非 OCPP 帧，不进入协议报文列表；CSMS 可在后续 `GetConfiguration` 中读取新值。

`packages/charging-point-actor` 拥有协议配置定义、校验、目录模型、运行副作用、串行修改命令及异步持久化端口，但不依赖 Drizzle、数据库表或 Hono。`apps/server` 的 `protocolConfiguration` 模块实现 PostgreSQL schema、repo、目录初始化与补齐、HTTP API、错误映射和 Actor persistence adapter；`@spark-bee/contracts` 只定义 API 契约，前端配置页面归属 charging-points feature。该依赖方向与现有 Actor 日志 Sink 和交易 Store 一致。
