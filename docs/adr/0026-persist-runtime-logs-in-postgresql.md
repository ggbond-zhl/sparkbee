# 运行日志持久化到 PostgreSQL

SparkBee 将桩实例的结构化运行日志持久化到现有 PostgreSQL，以支持 Render 休眠、重启或重新发布后的问题排查；本阶段只持久化运行日志，不持久化全部协议报文。未删除桩实例的运行日志滚动保留 7 天；删除桩实例时同步删除关联运行日志，避免保留无法从运行调试台访问的孤立诊断数据。

运行日志的结构化上下文原样写入数据库，不对密码、Token、Authorization、Cookie、API Key、数据库连接串凭据、CSMS URL 用户信息或查询参数进行脱敏。该选择优先保证调试信息完整性，测试与部署环境必须自行控制运行日志的产生内容、数据库访问权限和日志查询权限。

第一版不对 Heartbeat、MeterValues 等高频成功日志降采样，所有运行日志均完整保留，以优先保证调试时序并用真实数据评估容量；失败、拒绝和异常日志后续也不得参与降采样。

运行日志通过内存队列异步批量写入，单批达到 100 条或等待 1 秒时提交，以先到者为准。数据库写入失败不得阻断桩实例的启动、Heartbeat、交易等动作；短暂失败可以有限重试，最终失败写入服务标准错误。进程异常退出时接受丢失队列中最多约 1 秒的尾部日志，正常关停时在有限超时内尝试刷新队列。

数据库 Sink 替换现有 JSON Lines 文件 Sink，不进行数据库与文件双写，也不在数据库失败时回退写文件。本地开发和测试使用相同的数据库持久化路径；单元测试仍可注入内存 Sink。这样避免维护两套持久化行为及其一致性语义，Render 临时文件不再作为诊断数据来源。

运行调试台不展示持久化运行日志，只保留现有“事件”和“报文”页签，避免把业务操作与跨时间诊断查询混在同一界面。后端继续提供按时间、级别、日志类型和 `operationId` 精确匹配的游标分页查询接口，不提供自由文本全文搜索或任意 JSON 条件查询；后续另建独立日志查询页面使用该接口。同一操作的 `started` 与 `completed`、`rejected` 或 `failed` 记录通过 `operationId` 串联。运行日志仍是诊断信息，不作为业务状态来源。

共享测试环境沿用 ADR-0025 的公开、无登录边界，第一版允许任何能够直接访问 Render API 的调用方查询运行日志。团队明确接受密码、Token、连接凭据、`idTag`、桩身份、错误堆栈和完整业务上下文可能公开的风险；后续登录模块上线时必须把运行日志查询纳入鉴权与授权范围。

Supabase 在测试环境中只提供托管 PostgreSQL，前端不得通过 Supabase Data API 直接访问运行日志表。运行日志表启用 RLS，不向 `anon` 和 `authenticated` 角色授予访问策略或表权限；所有查询统一经过 SparkBee 后端 API，以保持分页、筛选和返回结构边界。正式环境切换到自部署 PostgreSQL 时，前端数据链路不因此改变。

7 天保留策略由 server 自主管理：进程启动后异步执行一次过期日志清理，持续运行期间在上一次任务结束 24 小时后再次调度。清理按小批次删除，不阻塞服务启动、HTTP 请求或桩实例动作；失败时写入标准错误并等待下一周期重试。Render 休眠期间不产生新日志，也不要求准点清理；服务下次唤醒后补做清理。该方案只依赖 PostgreSQL，正式环境切换到自部署数据库时无需更换调度机制。

该决定修正 ADR-0025 中测试环境不持久化运行日志的旧约束，同时保留 ADR-0013 中运行日志与协议事件、协议报文相互独立的边界。
