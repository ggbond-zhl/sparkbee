# 持久化协议报文与协议事件

SparkBee 将桩实例产生的协议报文和协议事件作为历史观察记录持久化到 PostgreSQL，用于跨页面、服务休眠、重启和重新发布后的调试回看；这些记录不参与恢复运行状态，也不作为业务判断的事实来源。协议报文与协议事件使用独立数据表，完整、未脱敏保存当前运行调试台两个观察页签中的真实记录；运行状态快照、桩实例删除通知和 Actor 日志不进入这两张表。无论是否存在 SSE 订阅者，运行中的桩实例都持续记录；桩实例停止后仍可查询历史，删除桩实例时同步删除关联记录。

两类历史观察记录均滚动保留 7 天。写入采用异步批量、有限重试的 best effort（尽力持久化）语义，数据库故障不阻断 Heartbeat、交易、远程命令或实时 SSE；进程异常退出时接受丢失约 1 秒尚未刷新的尾部记录，持久化失败写入服务端错误日志。该选择优先保证协议模拟可用性，代价是实时看到的极少量尾部记录可能尚未持久化。

SSE 继续只推送实时增量，不使用 `Last-Event-ID` 承担历史回放。运行调试台打开或刷新时，分别通过 `GET /api/charging-points/{id}/protocol-messages` 和 `GET /api/charging-points/{id}/protocol-events` 加载最近 200 条记录，并可用游标继续加载更早记录；页面使用持久化记录 ID 合并并去重 HTTP 历史与 SSE 增量。时间、事件类型、报文方向和 action 等观察筛选由服务端在完整 7 天保留范围内执行，而不是只过滤浏览器已经加载的记录。

共享测试环境沿用公开、无登录边界，团队接受完整 OCPP body、`idTag` 和错误详情可能被任何能够直接访问 Render API 的调用方读取。前端不得通过 Supabase Data API 直接访问历史观察表；表启用 RLS，且不向 `anon` 和 `authenticated` 角色授予访问策略或表权限，所有查询统一经过 SparkBee 后端 API。

本决策取代 ADR-0022 中“只保留当前页面会话、不提供刷新后历史或后端分页”的边界，但保留其虚拟列表和滚动钉住设计；保留 ADR-0012 的 SSE 不回放边界；修正 ADR-0026 中“只持久化 Actor 日志、不持久化全部协议报文”的范围，同时不改变 Actor 日志自身的持久化设计。
